# Closed healthy source 19e transport Stage upgrade

This prepares one upgrade of the three existing synthetic transport Stage
containers. **Deploy Stack** keeps its `colab-stage` scope and existing complete
production-host queue. There is no additional trigger, queue, receiver,
credential enrollment, identity reload, or production capability.

The new plan and its compiled candidate pin are deliberately unresolved. Native
publisher custody and the accepted Services plan are checked before SSH; the
same evidence is rechecked before receiving the host key. The shared canonical
guard refuses either an Axxium or Colab production hold before any Stage write.
A future reviewed pin must select an actual accepted new source and public
immutable image. Source 19e's warning-bearing baseline and historical Stage
receipt supply no new-candidate execution or production qualification.

The predecessor is the exact healthy source `19e` tuple from native run
`40963569096/1`: source `19e`, classic image configuration `6b107`, runtime/registry
manifest `8cd5`, Services `215fe`, plan `5c396` and compose `56c036`.
Its expected host receipt hash is
derived from the authenticated native receipt and the accepted producer's exact
host-file serialization; it is not a new live observation. Apply must match the
actual protected receipt bytes or refuse before effects. The old selector must
contain only its exact immutable image. Existing source definitions, three
actual containers, private client/fixture-token metadata, the already enrolled
dedicated Stage pair and existing active synthetic actor are checked before
claim. Native project membership uses `docker ps -aq --no-trunc` so the full
container-ID namespace matches `docker inspect.Id`.

After anonymous immutable image/GPL verification, the controller creates a
durable private hold and preserves the old receipt, selector and container
identities. It stops only the three captured Stage IDs, verifies a consistent
bounded snapshot and independent byte-identical restore copy, and updates only
the image selector. A failed or uncertain operation retains the hold, journal
and old/new state; it never retries effects, restores live OAuth files,
restarts a production service or automatically rolls back.

A graceful stop may checkpoint SQLite and remove its WAL/SHM files. The private
preflight manifest is retained, static fixture credentials must remain exact,
and the consistent stopped store is what is copied and restored. Database
integrity checks open a separate disposable verification copy; both exact
recovery copies remain unchanged.

The new containers must pass the existing real gateway/container/protocol and
OAuth/MCP fixture smoke. It exercises downstream PKCE/consent/token handling,
actual forwarding and compute-read boundaries, rejects execution, removes the
exact short-lived synthetic root session and proves revocation. The helper's
executed successful predicate count is retained. Fixture-token and client bytes
must be identical, and unrelated runtimes must match the transaction's fresh
preflight inventory. The old 165-predicate result cannot stand in for this new
run. Only then is a new receipt durably stored and atomically published, with
the prior receipt retained privately and hold removed last. Human login,
Google execution and production qualification remain explicitly false.

The same change fixes the prepared production preflight's full-ID query and
